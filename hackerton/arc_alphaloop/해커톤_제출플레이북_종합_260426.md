## 2. Phase 1: 사전 조사

### 2.1 해커톤 룰 정독

**필독 항목** (각 해커톤 페이지 또는 Discord에 있음):
- 마감 시간 + **타임존 명시** (KST 기준 변환 필수!)
- Track 종류 + 각 track 상금
- 영상 길이 한도 (lablab은 보통 ≤5분)
- on-chain tx 최소 갯수 (있으면)
- per-action pricing 한도 (있으면, 보통 ≤$0.01)
- 제출 양식 필수 필드 (영상 URL, GitHub, demo URL, 등)

### 2.2 선행 작품 스크랩 (NIH 금지)

```
✅ 같은 sponsor의 과거 해커톤 submission 페이지 스크랩
✅ 라이벌 작품의 GitHub repo 검토
✅ 클러스터 분류 (어떤 패턴이 다수, 무엇이 차별화 축)
✅ 30분 이내 끝낼 것 (over-scan 금지)
```

**도구**:
- `curl`, `gh`, WebFetch (Claude tools)
- 결과 → `docs/_<source>_scrape_<YYMMDD>.txt` (커밋 금지)

### 2.3 차별화 축 결정 (Garry Tan 식 ONE thing)

```
질문: "이 해커톤에서 우리만 할 수 있는 것은?"
예 (Arc 해커톤 우리 케이스):
  → "유일한 라이브 v1.3 production arb bot 백킹"
  → "다른 팀들이 mock 데이터 쓸 때 우린 8일 +$17.92 PnL"
```

이 한 줄을 **PDF 덱 cover, SUBMISSION.md, 영상 스크립트** 모두에 박아넣기.

## 3. Phase 2: 빌드

### 3.1 코어 시스템 (해커톤마다 다름)

**On-chain 해커톤 공통 패턴**:
- 컨트랙트 deploy → 주소 메모
- 5+ 개의 tx 생성해서 evidence 만들기
- Merkle root 같은 검증 가능한 anchor 생성

**AI agent 해커톤 공통 패턴**:
- LLM 호출 + tool use 데모
- 이미지/음성/영상 생성 결과물
- 메모리 시스템 (대화 지속성)

### 3.2 Evidence 파일 (judge 검증용)

```
docs/evidence/
├── batch_tx_hashes.txt       # tx hash 목록 (변조 검출 가능)
├── merkle_root.txt           # Merkle root
├── live_stats_<dates>.json   # 라이브 시스템 통계 (있으면)
└── ...
```

**중요**: SUBMISSION에서 링크 거는 모든 파일은 **GitHub에 push되어 있어야 함** (안 그러면 404).

### 3.3 GitHub 관리

```bash
# 처음 셋업
git init
git remote add origin https://github.com/<user>/<repo>.git

# 작업 중 자주 push
git add <specific files>  # NEVER `git add .` (.env 같은 secrets 위험)
git commit -m "<message>"
git push origin main

# .gitignore 필수 항목
.env
.env.local
.claude/
node_modules/
__pycache__/
*.pyc
```

**필수 섹션**:
1. What we built (3-5 문장)

### 4.3 큐시트 (영상 녹화용)

이게 핵심! 영상 녹화의 정확도를 결정.

**큐시트 구조**:
```
| 시간 | 들리는 멘트 | 화면 액션 |
|------|------------|-----------|
| 0:00 | "USDC is the gas." | PDF p.1 Cover |
| 0:04 | "I run a live arb bot..." | Alt+Tab → 대시보드 |
| 0:28 | "Per-signal value..." | PDF p.3 Problem |
| ... | ... | ... |
```

**3-segment 권장 구조** (4:20 기준):
```
Segment 1 (0:00 - 1:20)  Hook + Problem + Why <chain>
Breath gap (1:20 - 1:23) MP3에 ... ... ... 삽입
Segment 2 (1:23 - 3:19)  Live demo + RL/proof
Breath gap (3:19 - 3:23)
Segment 3 (3:23 - 4:20)  Originality + CTA
```

각 segment 끝에서 일시정지 가능 → 망친 부분만 재녹.

## 5. Phase 4: 영상 제작

### 5.1 음성 생성 — ElevenLabs

**플랜**: Starter $5/월 (Voice Cloning + Multilingual v2)

**워크플로우**:
1. https://elevenlabs.io 가입 + 결제
2. **Voice Cloning** → "Add Voice" → "Instant Voice Clone"
3. 본인 목소리 1-2분 녹음 → 업로드 (한국어 가능)
4. 클론 완성 (1분 이내)
5. **Speech Synthesis** → Voice 선택 → 스크립트 paste
6. **설정**:
   - Model: Multilingual v2
   - **Speed: 0.85x** (외국인 대상이면 약간 느리게)
   - Stability: 50%
   - Similarity: 75%
7. Generate → MP3 다운로드

**스크립트 작성 팁**:
- 영어로 작성 (영어 발음이 더 깨끗함)
- **Breath markers**: 문단 사이에 `... ... ...` 삽입 (segment 경계)
- 약어/발음 어려운 거 단어로 풀어쓰기 ("USDC" → "U S D C")
- 숫자 단어로 ("150" → "one hundred fifty")
- 너무 긴 문장 X (한 호흡으로 못 읽음)

**예상 길이**:
- 영어 단어 수 × 0.4초 ≈ 0.85x speed에서의 길이
- 489 단어 → 약 4:20 (실측)


**파일 다운로드**:

### 5.3 영상 + 음성 + 자막 합치기 — ffmpeg

**ffmpeg 설치** (Windows):
```powershell
winget install --id=Gyan.FFmpeg --silent --accept-package-agreements --accept-source-agreements
```

설치 후 PATH 인식 안 되면 직접 경로:
```
C:\Users\<user>\AppData\Local\Microsoft\WinGet\Packages\Gyan.FFmpeg_*\ffmpeg-*-full_build\bin\ffmpeg.exe
```

**음성만 입히기 (자막 없이)**:
```bash
ffmpeg -y -i video.mp4 -i audio.mp3 \
  -c:v copy -c:a aac -b:a 192k \
  -map 0:v:0 -map 1:a:0 -shortest \
  -movflags +faststart \
  output.mp4
```

**음성 + 자막 burn-in**:
```bash
ffmpeg -y -i video.mp4 -i audio.mp3 \
  -vf "subtitles=sub.srt:force_style='FontName=Arial,FontSize=16,PrimaryColour=&H00FFFFFF&,OutlineColour=&H00000000&,BackColour=&H80000000&,BorderStyle=1,Outline=1.0,Shadow=0.5,MarginV=50,Bold=0,Spacing=0.2'" \
  -c:v libx264 -preset fast -crf 20 \
  -c:a aac -b:a 192k \
  -map 0:v:0 -map 1:a:0 -shortest \
  -movflags +faststart \
  output.mp4
```

**자막 스타일 권장값** (보드라운 느낌):
- FontSize: 16-18
- Bold: 0 (절대 1로 하지 마. 너무 굵음)
- Outline: 1.0-1.5
- Shadow: 0.5
- BackColour: 80000000 (반투명 검정 배경)

### 5.4 자막 (SRT) 처리

**원칙**: ⚠️ Burn-in 자막은 **타이밍 맞추기 매우 어려움**. 마감 임박이면 **YouTube CC track 권장**.

**Burn-in 자막 vs YouTube CC track**:

| 항목 | Burn-in (ffmpeg) | YouTube CC |
|------|------------------|------------|
| 영상 수정 | 재인코딩 필요 | 즉시 가능 |
| 타이밍 보정 | 수동 | 자동 (음성 분석) |
| 다국어 | 영상 N개 | 자동 번역 |
| 시청자 toggle | X (강제) | O |
| 위험도 | 망치면 보임 | 안전 |

**권장 워크플로우**:
1. Burn-in 시도 → 타이밍 1-2번 어긋나면 즉시 포기
2. 깨끗한 영상 (자막 없음) 만들기 → YouTube에 SRT 첨부

**SRT 자동 매핑 스크립트** (시간 안 맞으면):
```python
# rescale_srt.py — piecewise linear interpolation
# anchors: [(원본 SRT 시간, 실제 MP3 시간), ...]
# 예: (0, 0), (30.2, 28), (75, 80), ...
```

**SRT 문장 단위로 합치기** (짧은 entry들이 너무 빨리 바뀌는 거 방지):
```python
# merge_srt.py — 마침표(. ! ?)로 끝나는 곳까지 묶기
# 또는 70자 넘으면 분리
```

### 8.10 ⚠️ 트랙 multi-select 안 함 (NEW, 260426 추가 — 가장 큰 미스)

**증상**: 트랙을 1개만 선택해서 1개 후보군에서만 경쟁.

**원인**: 폼에 트랙이 multi-select 가능한데 1개만 골라도 진행됨. 폼 UX가 1개만 골라야 하는 것처럼 보임.

**Arc 해커톤 사례 (260426 AlphaLoop)**:
- 우리: Track 2 (Agent-to-Agent Payment Loop) 1개만
- ArcAgent: 4개 트랙 (Per-API + Agent + Usage + Real-Time)
- QuantMesh: 3개 트랙
- SwarmPay: 2개 트랙
- AgentMesh: 2개 트랙
→ 우리만 1개. 후보군에서 자동으로 손해 봄

**해결**:
1. 제출 폼 채우기 전 → 트랙 정의 정독
2. 우리 프로젝트가 자격되는 트랙 모두 체크리스트
3. 자격된 트랙은 **무조건 모두 선택**
4. 심사관이 "이건 우리 트랙 아닌데" 빼는 건 OK, 안 골라서 후보군에 못 들어가는 건 회수 불가

**판정 기준**: "우리 프로젝트가 그 트랙 정의의 50% 이상 부합하면 선택"
- AlphaLoop가 "Per-API Monetization"에 자격? → x402 API + per-request pricing 있음 → 90% 자격 → 선택해야 했음
- AlphaLoop가 "Real-Time Micro-Commerce"? → 150 micro-commerce events + sub-sec settlement → 90% 자격 → 선택해야 했음
- AlphaLoop가 "Usage-Based Compute Billing"? → LLM inference + paper-trade compute per signal → 70% 자격 → 선택했어야 했음

### 8.11 ⚠️ "Closed Loop" 화법의 함정 (NEW, 260426)

**증상**: "내 봇이 내 봇한테 신호 산다" = 사업 모델 모호함.

**문제**:
- 심사관이 "이걸 외부 누가 사용함?" 의문
- B2B 마켓플레이스 (QuantMesh) / 양면 시장 (SwarmPay) / B2C (AgentMesh) 보다 약함
- "기술적 정직성"보다 "사업화 가능성" 비중 두는 심사 기준에서 불리

**해결**:
- 심지어 closed loop 프로젝트라도 **외부 buyer 페르소나 명시**
  - "현재는 closed loop, 향후 외부 트레이딩 봇/펀드/리서치 데스크에 신호 판매"
  - "B2B SaaS 모델 가능, $X/month per signal subscription"
- Description에 "Future commercialization" 섹션 1단락 추가
- 영상 마지막 10초에 "this scales to..." 외부 확장성 멘트 추가

### 8.12 ⚠️ 마진 화법 = 충격적 숫자 (NEW, 260426)

**약함 (우리 화법)**: "Sub-cent pricing $0.0005-$0.010"
**강함 (QuantMesh 화법)**: "$0.002 신호가 Ethereum이면 $1.50 = -74,900% margin"

**원리**: 심사관 머리에 박히는 건 **충격적 숫자 1개**. 범위/평균이 아니라 극단값.

**템플릿**:
```
"On Ethereum, this would cost $X gas per $Y action = -Z% margin (impossible).
On Arc, same action costs $0.0001 gas = +99.X% margin (viable)."
```

→ 마이너스 % + 4자리 숫자 = 기억에 남음
→ Description / Video / Deck 모두 같은 화법 통일

### 8.13 ⚠️ "와우 모먼트" UX 1개 필수 (NEW, 260426)

**약함 (우리)**: 정적 대시보드 + 카드들
**강함 (AgentMesh)**: "waterfall feed with truncated hashes, USDC amounts, settlement latency 실시간"

**원리**: 심사관 영상 30초 본 후 인상에 남는 건 **시각적 한 장면**.

**예시**:
- 실시간 트랜잭션 waterfall (해시 흐르는)
- agent → agent 송금 애니메이션
- balance 게이지 실시간 변화
- 가격 차트 + tx 마커 동시 흐름

**최소**: 영상 안에 "10초 동안 화면이 살아있는" 구간 1개

### 8.14 ⚠️ ERC-8004 (또는 표준) — 깊이 vs 폭 (NEW, 260426)

**약함 (우리)**: 5개 agent 등록 (Identity Registry만 사용)
**강함 (SwarmPay)**: 6개 agent + ERC-721 NFT + giveFeedback() Reputation Registry + EIP-712 setAgentWallet

**원리**: 솔로/소팀이면 **표준 1개를 깊이 파는 게** 5개 등록보다 강력.

**판단 기준**:
- 표준의 sub-component 모두 활용했는가?
  - ERC-8004: Identity / Reputation / Validation 모두?
- 표준 외 cryptographic primitives 결합?
  - EIP-712 / ERC-4337 / ERC-721
- 표준의 "고급" 기능 사용? (단순 register 넘어서)

### 11.1 ffmpeg 영상 합치기 함수 (Python wrapper)

```python
import subprocess
from pathlib import Path

FFMPEG = "C:/Users/<user>/AppData/Local/Microsoft/WinGet/Packages/Gyan.FFmpeg_*/ffmpeg-*-full_build/bin/ffmpeg.exe"

def merge_audio_video(video_mp4: Path, audio_mp3: Path, output_mp4: Path,
                     subs_srt: Path = None, font_size: int = 16):
    cmd = [FFMPEG, "-y", "-i", str(video_mp4), "-i", str(audio_mp3)]
```

### 11.2 SRT Rescaling (anchor-based piecewise linear)

```python
import re
from pathlib import Path

# anchors: list of (original_seconds, mp3_seconds)
ANCHORS = [
    (0.5, 0.0),       # phrase 1 start
    (30.2, 28.0),     # phrase N start (validated)
    (75.0, 80.0),     # segment 1 end
    (75.2, 83.0),     # segment 2 start (after 3s breath)
    # ... add more anchors as needed
    (211.0, 260.0),   # end
]

def remap(t: float) -> float:
    if t <= ANCHORS[0][0]: return ANCHORS[0][1]
    if t >= ANCHORS[-1][0]: return ANCHORS[-1][1]
    for i in range(len(ANCHORS) - 1):
        s0, d0 = ANCHORS[i]
        s1, d1 = ANCHORS[i+1]
        if s0 <= t <= s1:
            return d0 + (t - s0) * (d1 - d0) / (s1 - s0)
    return ANCHORS[-1][1]

def parse_ts(s: str) -> float:
    h, m, rest = s.split(":")
    sec, ms = rest.split(",")
    return int(h)*3600 + int(m)*60 + int(sec) + int(ms)/1000

def fmt_ts(t: float) -> str:
    if t < 0: t = 0
    h, m, s = int(t//3600), int((t%3600)//60), int(t%60)
    ms = int(round((t - int(t)) * 1000))
    if ms == 1000: ms, s = 0, s+1
    return f"{h:02d}:{m:02d}:{s:02d},{ms:03d}"

def rescale_srt(src: Path, dst: Path):
    content = src.read_text(encoding="utf-8")
    blocks = re.split(r"\n\s*\n", content.strip())
    ts_re = re.compile(r"(\d\d:\d\d:\d\d,\d\d\d)\s*-->\s*(\d\d:\d\d:\d\d,\d\d\d)")
    out = []
    for blk in blocks:
        lines = blk.split("\n")
        for i, line in enumerate(lines):
            m = ts_re.match(line)
            if m:
                t1, t2 = parse_ts(m.group(1)), parse_ts(m.group(2))
                lines[i] = f"{fmt_ts(remap(t1))} --> {fmt_ts(remap(t2))}"
                break
        out.append("\n".join(lines))
    dst.write_text("\n\n".join(out) + "\n", encoding="utf-8")
```
