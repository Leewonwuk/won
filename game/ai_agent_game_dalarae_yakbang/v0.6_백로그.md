- 후보 수정: (a) 선비도 환영 스폰 대상에 포함 (`_pendingWelcomeTier = 'seonbi'`), (b) 혹은 해금 토스트에 "곧 찾아올 것" 문구 추가.
- 처리 제안: **Phase 4-C** 또는 **Phase 6**. 환영 스폰 확장은 간단하므로 Phase 4-C 가 적합.

### Mid: 명의 누적 속도 밸런스 주석 _(GA Smoke #3)_
- 증상: `tierThresholdByMyeongui = { nongmin: 10, sangin: 15, seonbi: 40, yangban: 100 }` 가 코드에만 있고, 체감 타이밍(몇 주차 근처 해금) 주석 없음. 밸런스 튜닝 시 의도 소실 위험.
- 후보 수정: `config.js` 상단에 "기준 플레이 스냅샷" 주석 추가 — "nongmin ≈ Week 2 초, sangin ≈ Week 3, seonbi ≈ 1월 말, yangban ≈ 2월 초" 등.
- 처리 제안: **Phase 5** 경제 밸런싱 시 캘리브레이션과 함께.

### Low: 가중치 동적 조정 _(GA Smoke #5)_
- 증상: `tierSpawnWeight` 는 정적 상수 (`nobi: 6, nongmin: 3, sangin: 2, ...`). 게임 진행도와 무관히 nobi 가 항상 가장 자주 등장.
- 영향: 후반부에도 노비 비중 과다 → 상위 계층 해금 보상감 희석.
- 후보 수정: 월/명의 구간별 가중치 테이블, 혹은 현재 해금 계층 중 가장 높은 tier 의 가중치 증가.
- 처리 제안: **Phase 5** 밸런싱.

### Low: FloatingText 중복 오버레이 확장 _(GA Smoke #6, §7 Low merge)_
- 증상: §7 Low "다중 환자 FloatingText 좌표 겹침" 과 동일 범주. Phase 4-B 에서 거절 시 별도 floating 없지만 향후 거절 피드백 추가 시 재발 가능.
- 처리 제안: **Phase 6 UX 폴리시** 기존 §7 Low 항목에 묶어 처리. 추가 티켓 생성 없이 범위만 확장.

### Low: `_noStaffToastShownByBuildingTier` prefix 매칭 미래 호환성 _(Bug Hunter P2-2)_
- 증상: `StaffPanel` 의 "직원 배치됨" 시 prefix `${building.key}_` 로 guard Set 정리. 현재 building.key 가 모두 `_` 없는 단일 단어 (`acu`, `herb`, `haewoso`, `gukbap` 등) 라 안전. 향후 `herb_room_a` 같은 key 추가 시 오매칭 위험.
- 후보 수정: key 명명 규약 주석으로 `_` 금지 명시, 또는 guard Set 을 `Map<buildingKey, Set<tier>>` 구조로 변경.
- 처리 제안: **Phase 6** 또는 새 building 도입 시. 현 단계에선 `BuildingRegistry.js` 상단에 "key 는 `_` 없는 단일 식별자" 규약 주석 1줄로 충분.
