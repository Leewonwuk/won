## 0. 30초 요약 (TL;DR)

- **무엇**: 동양 판타지 한의원 경영 시뮬. 카이로소프트 *온천물어* 오마주 + 한국 한의원 + 일구이침삼약(뜸→침→약→약탕) 철학.
- **스택**: Phaser 3.60 + Tone.js 14.8, **빌드 도구 없음**(브라우저 ES module). `npx serve`만 있으면 즉시 실행.
- **현 위치**: v0.7 릴리스(2026-04-20) 완료. Phase 7-A(살아있는 환자) + 7-B(공간 퍼즐 밀도) 완. 다음 권장 진입점은 **Phase 4-C(티켓 시스템)** 또는 **Phase 7-B sprite 단위 통일**.
- **최종 목표**: 웹이 아니라 **게임앱**. 앱화 경로 = Capacitor 래핑(2026-04-19 결정). Phaser 유지, 아트는 사용자/아내분이 친필 공급 → Claude는 로드·애니·이벤트만.

## 1. 즉시 실행 (1분 안에 게임 띄우기)

```bash
cd C:/Users/user/game/Kario
npm run start          # = npx serve src-v0.7 -l 3000
# 브라우저: http://localhost:3000
```

이전 버전 실행도 가능:
- `npm run start-v06` → :3006
- `npm run start-v05` → :3005

**의존성 설치 불필요**. `package.json`은 메타정보만이고 실제 런타임은 CDN(Phaser/Tone.js).

- `P` 환자 강제 스폰
- `T` 튜토리얼 워커(레거시 — 백로그 §9 Mid에 교체 예정)
- `Y` 다음 주 경계로 시간 점프 (주간 결산 빠른 확인)
- `F2~F5` 농민/상인/선비/양반 디버그 스폰
- `H` 무수리 강제 고용 (Phase 3-B QA 잔존)

## 6. 반드시 지켜야 할 작업 규약 (광역)

`CLAUDE_GLOBAL_RULES.md` + 메모리에 누적된 핵심만 발췌:

### A. 거인의 어깨 (최우선)
- 매 Phase 묶음 끝나면 병렬 검증 4종 필수: ①버그 헌터 ②코드 품질 ③GA 스모크 ④**거인의 어깨 평가자(생략 금지)**.
- 평가자 프롬프트엔 "체크리스트 PASS 여부 + 거장별 Failure Mode + 현 결과물 근접도" 3요소 요구.
- 6거장 = Sawyer/Molyneux/Wright/카이로/Daniel Cook/**Pedro Medeiros**(픽셀 도트 검수). 항목 ID로 참조: S1·M2·W1·K1·C2·P3 등.
- 출처: `docs/GIANTS_SHOULDERS.md`.

### B. 체크리스트는 3개씩
- 한 번에 다 처리 금지. 3개 묶음 → 검증→구현→합의→다음 묶음.
- 모호한 결정은 **반드시** 사용자에게 질문 (혼자 판단 금지).
- 완료 시 `[ ]` → `[x]`. 부분 완료는 `[~]`.

### C. 보고는 풀어서 (축약어 금지)
- 사용자 의사결정 청할 때 `C1`/`H-3`/`P0`·`payload`·`null 경로`·`emit`·`Chebyshev` 같은 축약·기술용어 **금지**.
- 3요소 포맷: ① 구체 시나리오(플레이 한 장면) → ② 유저 체감(1줄) → ③ 수정 이유(고치지 않으면 무엇이 깨지나).
- 축약어는 체크리스트·백로그·코드 주석에서**만** 허용.

### D. v0.6 → v0.7 전환 성격
- 단순 패치 누적 아님. v0.5는 큐매칭 게임이었고 v0.6에서 카이로식 10×10 그리드로 **사실상 코어 리라이트**.
- **Act II 요괴(도깨비·구미호·호랑이·산신령)는 v0.6에서 일단 폐기**. PRD.md는 v0.5 기준이라 그대로 믿으면 안 됨. v0.7에서 다시 도입하려면 사용자 합의 필요.
- 변수명 `명의` (not 명예/명성).

### E. 카이로식 렌더링 — 옵션 B 채택
- 건물·소나무: `origin=(0.5, 1)`, `y=타일 하단 경계`, `depth=20+row` (아래 행이 위 행 가림).
- 상단 32px이 위 타일 위로 튀어나와 카이로 "건물이 타일보다 큼" 체감.
- `GridSystem.isTallSprite()` 판정. 새 tall asset 추가 시 후보 업데이트.

### F. 에셋 파이프라인
- 캐릭터: `palette_transfer.py` + `recompose_via_components()` (Pedro 12색 팔레트 + connected-component 재조립). 64×64 프레임, RPG Maker MV 3열×4행.

- 건물: `resize_buildings.py` — 64×96 bottom-align (Phase 7-B 단위 통일 시 96→128 또는 64로 결정 예정).
- 원본 수정 시 파이썬 스크립트 재실행 필수. 에셋은 커밋된 상태 아닌 생성물.

## 7. 위험 포인트 (걸려 본 흙탕물)

신규 에이전트가 모르고 들어가면 같은 함정에 빠질 만한 것들.

### 7.1 Phase 4-A 사전 검증 보고 반려 사건
- 사용자가 'CRITICAL 4건 / 축2 2/5' 식 축약 보고를 보고 "무슨말인지 모르겠다"고 반려.
- 교훈: 의사결정 청할 때 **항상** 시나리오·체감·이유 3요소 풀어쓰기. 메모리 `feedback_explain_why.md`에 영구 박혀있음.

### 7.2 양반 환영 스폰 경로 부재
- Phase 4-B 1차에서 양반 해금 순간 결정적 환영 스폰을 추가했는데, 환영 patient가 **경로 없어 즉시 abandoned** 시 해금이 소실되는 버그가 GA Smoke에서 발견됨.
- 봉합: `Patient.isWelcomeSpawn` 플래그 + abandoned 분기에서 `_pendingWelcomeTier` 재설정으로 차단.
- 다음 환영 스폰 추가 시(선비 등) 같은 재설정 패턴 따라갈 것.

### 7.3 destroy() 강제 평가 주석 vs 실제
- `PatientSystem.destroy()` 주석은 "리스너 살아있어 카운터에 반영" 이지만, 실제 `_onShutdown`이 `events.off(...)`를 `destroy()`보다 먼저 부름 → shutdown 직전 환자 1~2명 카운터 누락.
- 백로그 §10 Mid에 정리됨. Phase 4-B 종료 시점에 주석 정리하거나 호출 순서 교체 합의됨(아직 미반영).

### 7.4 국밥집 해금 4배 빨라짐
- `unlockChain.gukbap.count: 30` (any 카테고리) — 환자 1명당 최대 4건 `patient_served` emit (뜸+해우+우물+국밥). 실질 환자 7~8명에 해금 도달.
- 백로그 §9 Mid. Phase 4-D 또는 1차 밸런스 패스 시 통합 조정 합의됨.

### 7.5 Y 키 fast-forward DEV 게이팅 부재
- `_debugFastForwardWeek`가 프로덕션 빌드에서도 활성. 첫 공개 빌드 직전 게이팅 필수.
- 백로그 §3.

### 7.6 카이로 6거장 평가에서 반복 등장하는 FAIL
- **Crawford "계층 질적 차별화"** — 노비/농민/상인/선비/양반이 단순 소지금/만족도 차이일 뿐, 편의 선호·치료 품질 요구·평판 전파 같은 메카닉 차이가 없음. Phase 4-C/6에서 보강 합의됨.
- **W2 시스템 간 상호작용** — v0.7 우물 확장/클러스터 페널티로 일부 보강. 직원·인접·경로 3자 루프는 아직 약함.

### 7.7 환자 sprite depth row 미적용
- 건물·소나무는 `depth=20+row` 카이로 오버플로 적용됐는데 환자 sprite는 미적용 → tall 건물 상부와 깊이 꼬일 가능.
- `PatientSystem`에서 `sprite.setDepth(30 + row)` 동적 갱신 검토 메모만 있음.
